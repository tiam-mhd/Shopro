# اتصال لندینگ به آیتم فعلی Shopro در Runflare

لندینگ در `apps/marketing` build مستقل دارد، اما در production داخل image ریشهٔ مخزن ساخته و از همان آیتم Docker موجود Shopro پاسخ داده می‌شود. هیچ پروژه، آیتم، سرویس، پورت، شبکهٔ خصوصی یا پایگاه‌دادهٔ تازه‌ای نسازید. سرویس فعلی روی `PORT=3000` می‌ماند؛ برنامه با توجه به Host درخواست تصمیم می‌گیرد رابط فعلی Shopro را بدهد یا لندینگ را.

## تنظیم دامنه و شبکه در همان آیتم

1. در همان پروژهٔ Runflare که Shopro در آن است بمانید. میزبان لندینگ را خودتان انتخاب کنید؛ این راهنما از روی `shoproapp.ir` ساب‌دامین حدس نمی‌زند.
2. میزبان انتخابی را در مدیریت دامنه‌های Runflare به‌عنوان دامنه/ساب‌دامین اضافه کنید. راهنمای Runflare برای ساخت ساب‌دامین، نام را بدون `http://` یا `www` می‌خواهد: [ساخت ساب‌دامین](https://runflare.com/docs/create-sub-domain/).
3. از بخش اتصال دامنه، همین میزبان را به **سرویس Docker فعلی Shopro** وصل کنید. در فهرست سرویس‌ها آیتم موجود را انتخاب کنید؛ آیتم دیگری نسازید. Runflare روند انتخاب سرویس موجود برای اتصال دامنه را مستند کرده است: [اتصال دامنه به سرویس](https://runflare.com/docs/add-domain-to-service/).
4. مقصد شبکه همان listener فعلی آیتم و پورت داخلی `3000` است. دامنهٔ فعلی محصول را جابه‌جا یا حذف نکنید. هر دو میزبان به همان سرویس می‌رسند و تشخیص Host در برنامه آن‌ها را جدا می‌کند.
5. اگر پنل برای دامنه تنظیم DNS یا SSL نشان داد، از همان مقادیر و وضعیت ارائه‌شده در پنل استفاده کنید. این راهنما رکورد A/CNAME یا IP حدس نمی‌زند و DNS را تغییر نمی‌دهد.

مقادیر موردنظر در تنظیم دامنه:

```text
پروژه: همان پروژهٔ فعلی Shopro
آیتم/سرویس: همان آیتم Docker فعلی Shopro
دامنهٔ جدید: <میزبانی که مالک انتخاب می‌کند>
مقصد دامنه: همان آیتم Docker فعلی
پورت داخلی مقصد: 3000
HTTPS/TLS: برای همان دامنه در Runflare فعال شود
آیتم یا شبکهٔ خصوصی جدید: ایجاد نشود
```

راهنمای عمومی Runflare اتصال یک دامنه به سرویس موجود را توضیح می‌دهد. جزئیات فیلد شبکه در پنل هر حساب از اینجا قابل مشاهده نبود؛ این راهنما فقط همان اتصال مستندشده به سرویس فعلی و پورت فعلی را لازم می‌داند.

## متغیرهای محیطی

در Bulk Edit آیتم Docker فعلی، `PORT` را روی مقدار فعلی `3000` نگه دارید و این دو مقدار را اضافه کنید. پیش از ذخیره، فقط میزبان نمونه را با origin واقعی انتخابی خودتان جایگزین کنید؛ مقدار باید HTTPS و بدون مسیر باشد.

```dotenv
PORT=3000
MARKETING_PUBLIC_URL=https://landing-host-replace.example
PRODUCT_URL=https://shoproapp.ir
```

`WEB_ORIGIN` فعلی Shopro و بقیهٔ متغیرها و Secretها را حفظ کنید؛ دامنهٔ لندینگ را به `WEB_ORIGIN` اضافه نکنید. لندینگ برای نمایش خود API یا دیتابیس را فراخوانی نمی‌کند. `MARKETING_PUBLIC_URL` باید با `WEB_ORIGIN` متفاوت باشد تا صفحهٔ محصول و لندینگ جابه‌جا نشوند. `PRODUCT_URL` origin فعلی محصول است و مسیر دکمه‌های ورود از آن به `/app` ساخته می‌شود. اگر origin محصول در آینده عوض شد، همین مقدار را به‌روز کنید.

`MARKETING_PORT` یا `PUBLIC_URL` را در آیتم موجود تنظیم نکنید. پورت مستقل `8080` فقط برای پیش‌نمایش کانتینری جداست و در اتصال Runflare این راهنما استفاده نمی‌شود.

نمونهٔ این متغیرها در [infra/runflare.env.example](../infra/runflare.env.example) آمده است. خط نمونهٔ دامنه را قبل از استقرار جایگزین کنید.

## ساخت و اجرای production

Dockerfile ریشه build اصلی را انجام می‌دهد و بعد دارایی‌های مستقل لندینگ را هم می‌سازد. image همان آیتم Runflare فعلی را با build معمول مخزن به‌روز کنید؛ Dockerfile جدا یا آیتم تازه نسازید. API همچنان روی `0.0.0.0:3000` اجرا می‌شود.

محتوای لندینگ خودش API یا دیتابیس را فراخوانی نمی‌کند؛ بااین‌حال چون طبق خواسته در همان آیتم فعلی سرو می‌شود، شروع و دسترس‌پذیری آن تابع همان سرویس است. entrypoint فعلی پیش از اجرای API، migration دیتابیس را اجرا می‌کند؛ اگر آن مرحله مانع بالا آمدن سرویس شود، لندینگ همان آیتم نیز پاسخ نمی‌دهد.

درخواست‌هایی که Host آن‌ها برابر `MARKETING_PUBLIC_URL` است، محتوای `apps/marketing/dist` را می‌گیرند. درخواست‌های میزبان فعلی محصول، همان web app و API قبلی را می‌گیرند. روی میزبان لندینگ مسیر `GET /healthz` پاسخ `200` می‌دهد؛ health check محصول در `/api/v1/health/live` و `/api/v1/health/ready` باقی می‌ماند.

برای پیش‌نمایش مستقل محلی، از ریشهٔ مخزن اجرا کنید:

```powershell
npm run dev --prefix apps/marketing
npm run build --prefix apps/marketing
npm run start --prefix apps/marketing
```

پیش‌نمایش `dev` روی پورت `5174` و server build مستقل روی `8080` است. این دو پورت برای Runflare استفاده نمی‌شوند. build کامل مخزن همان `npm run build` ریشه است؛ Dockerfile ریشه build لندینگ را هم اجرا می‌کند.
