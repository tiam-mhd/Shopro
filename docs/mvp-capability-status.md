# Shopro MVP capability status

This is an implementation status record, not a claim that the remaining MVP work is complete. Items marked **Open** remain release work under audit finding F-14.

| Capability | Current state | Evidence and remaining work | Technical reason it remains open |
|---|---|---|---|
| Expense receipt attachments | Partial | Expense drafts now support private upload/download/removal for owners, managers and accountants. Uploads are branch-scoped, limited to 10 MiB, checked by file signature (PDF/JPEG/PNG/WebP), stored under opaque keys outside public web roots, downloaded as attachments with `nosniff` and `no-store`, and audited without file bytes or names. Downloads require both the active session and a signed, scope-bound 60-second token sent in a request header. Unit tests cover checksum, token expiry/tampering and storage path guards. A real PostgreSQL HTTP integration test verifies multipart upload, file bytes and response headers, business/branch/user-scoped access, role denial, download-grant binding, audit metadata, and deletion from private storage. | Attachments require an absolute `ATTACHMENT_STORAGE_DIR` backed by a private persistent volume when enabled; the current Runflare service configuration has not been checked for durable volume support or configured. With the variable empty, attachment upload/download is disabled. Storage lifecycle/retention, multi-replica storage, and browser acceptance remain unverified. Files cannot be changed after posting. |
| Report and statement exports | Partial | Profit/loss, cash-flow, party-statement, inventory, sales-summary, current receivables/payables, and owner/accountant trial-balance screens can download Persian UTF-8 CSV with formula-leading cells escaped. Party-statement, inventory, receivable, and payable exports fetch cursor pages and stop safely at 10,000 rows; receivable/payable APIs aggregate in PostgreSQL and use a tenant/branch-checked `(normalized_name, id)` cursor. Receivable/payable exports are current balances, not period-filtered. A PostgreSQL 17 fixture with 10,000 products, 11,516 parties and 100,024 journal lines passed receivable and statement counts 0, 1, 499, 500, 501, and 10,000, same-day cursors, independent statement aggregate totals, branch isolation, tie-key pagination, reversal netting, and Rial-total checks. The financial fixture reconciled partial/full sale returns, refund limits, concurrent returns, concurrent idempotent sale/purchase/expense voids, dashboard, profit/loss, cash flow, receivables/payables, inventory and ledger. The latest 100-page 10,000-row cursor walk took 1.764 s. Statement query plans used the party/journal composite index (latest run: 501 rows 8.20 ms, 10,000 rows 13.92 ms); receivable first-page execution was 25.93 ms. The latest synthetic 20-VU/300-second HTTP profile completed 37,395 read requests and 417 balanced sale postings with zero errors. | Remaining report formats, PDF/Excel, browser download acceptance, other reversal reconciliations and full endpoint-to-ledger accounting acceptance are missing. The local database result is synthetic and does not replace production-scale profiling. |
| Database and attachment backup/restore | Partial | `npm run backup:create` writes an encrypted PostgreSQL custom dump and, when needed, all receipt files present in attachment metadata after checking their size and SHA-256. AES-256-GCM is authenticated; an advisory lock coordinates receipt mutations with the snapshot. A restore CLI verifies artifact checksums and GCM tags, limits destinations to a confirmed loopback `shopro_restore_*` database with no user tables or extra schemas, validates core schema/migration rows, and verifies restored attachment checksums. Retention requires an explicit day count and prunes only generated backup directories. The full PostgreSQL 17 dump/restore round-trip passed on an isolated temporary cluster, including migration/seed, row-count comparison and receipt checksum comparison. | No external durable backup destination, scheduler, alerting, key escrow/rotation, RPO/RTO policy, or Runflare runner/volume has been configured or verified. Restore is an operator CLI, not a settings-page workflow. |
| Ledger and audit browsing | Partial | The finance area now includes a journal-line browser filtered by date and account, scoped to the active business/branch, cursor-paginated, with filtered debit/credit totals and formula-safe CSV export. Owners also have a business-scoped audit API and settings view with actor/action/entity/date filters, cursor pagination and a CSV download capped at 10,000 rows. The audit browser exposes event metadata only; it does not return audit before/after JSON. | Ledger/audit HTTP and browser access tests, CSV browser-download acceptance and large-history database profiling remain unrun. |
| Offline synchronization status | Partial | The browser queue now shows pending, syncing, succeeded, failed and conflict status per sale. It distinguishes transient failures from validation/server conflicts, requires a manual retry for transient failures, stops automatic retries on conflicts, and blocks branch-mismatched sends until the original business and branch are selected. `POST /sync/operations` now accepts a sale-create-and-post operation, claims it atomically with a processing lease, binds its id to the user/business/branch and payload hash, and reuses the existing draft/post idempotency keys. `GET /sync/status` returns cursor-paginated statuses scoped to the current user and branch. PostgreSQL integration verifies concurrent delivery creates one invoice and journal, and rejects changed payloads and cross-user/branch operation reuse. After server-confirmed posting the client removes the sale/payment payload and retains the receipt status for seven days. Logout warns about unsent records and requires an online server logout. | Sync currently handles only sale creation/posting; other operation types and user-facing conflict resolution are not implemented. IndexedDB/browser tests for actual offline sales, cold launch, refresh/logout isolation and real duplicate posting remain open. The offline IndexedDB payload is not encrypted. |
| Business-member administration | Partial | Owners can add members to selected active branches, change role and branch assignments, suspend/reactivate memberships, and view up to 100 access events. Updates and audit events share one transaction; the request guard checks active membership on every request. Non-owner member listings mask phone numbers. Service and HTTP tests verify phone masking, owner-only history/role changes/audit, cashier report denial and viewer write denial. The source-derived backend policy is recorded in [role-permission-matrix.md](role-permission-matrix.md). | Manager/accountant allow paths across all modules, the full role × endpoint matrix, and browser/device verification remain incomplete. System-admin operations remain a separate open capability. |
| System-administrator operations | Partial | Admin OTP sessions now have isolated session and CSRF validation, logout, a read-only overview, cursor-paginated business summaries that omit member phones, and a separate metadata audit log. Guard/service tests cover session separation, CSRF, scoped output and audit writes. | This is an API, not a graphical console. Admin list/audit HTTP acceptance and retention/alerting are not configured; the API intentionally does not mutate business data. |
| Banking, payment gateway, payroll, marketing CRM, multi-currency | Deferred by product scope | These are integrations or product domains outside the first-version scope in the provided specification. | Keep extension boundaries; do not represent them as implemented MVP functionality. |

## Release implication

F-14 remains open. CSV exports now cover additional operational and financial reports, but PDF/Excel formats and browser/download acceptance evidence are missing. Attachments use a private filesystem adapter and are included in the encrypted backup CLI; the isolated PostgreSQL round-trip passed, while a configured durable volume, external backup destination/schedule, and browser authorization tests remain open. Receivable/payable APIs and exports use bounded cursor pagination. Sale posting, partial/full return, sale/return/purchase/expense void, and their tested dashboard, P&L, cash-flow, receivable/payable, inventory and ledger effects now reconcile in a synthetic PostgreSQL fixture. Other reversals, HTTP/browser report acceptance, and complete endpoint-to-ledger reconciliation remain open. The sale-specific server sync API now deduplicates concurrent offline submissions and exposes user/branch-scoped status, but browser offline acceptance, conflict resolution and sync for other operation types remain open. The PWA update click now waits for service-worker control and provides recovery actions; the smoke test verifies the stale-prompt failure path, not a real two-version rollout. System administration now has an authenticated, audited read-only API but no graphical console. The restore tool is deliberately CLI-only and restricted to a confirmed local disposable database; no production database has been restored. No public file storage, user-supplied database commands, or unsupported backup guarantees were added. The remaining items above need implementation and acceptance tests before the specification's full MVP Definition of Done can be claimed.
